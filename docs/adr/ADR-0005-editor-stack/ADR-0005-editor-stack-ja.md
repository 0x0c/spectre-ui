## 文脈

画面を編集するのはエンジニアではありません。企画、マーケティング、カスタマーサポートの担当者です。
彼らに必要なのは、閉じたコンポーネントカタログの組み合わせで画面を構成できる、ブラウザ上のWYSIWYG
エディタです。WYSIWYG は What You See Is What You Get の略で、見たままが得られることを指します。そして
公開前に、「表示されているもの」を信用できる必要があります。

## 検討した選択肢

以下の決定の各行には、それぞれ比較対象がありました。根拠の節では、なかでも影響の大きい2つの選択を扱い
ます。フレームワークは React と TypeScript の組み合わせか、Svelte のようなコンパイル時フレームワークか、
という比較でした。状態管理は不変パッチ方式のストアか、CRDT（Conflict-free Replicated Data Type、競合
しない複製データ型）か、という比較でした。

## 決定

| 領域 | 採用 | 理由 |
| --- | --- | --- |
| フレームワーク | React 19、TypeScript、Vite | エコシステムと採用のしやすさに加え、マニフェスト由来の型をそのまま使えます |
| ドラッグ&ドロップ | `dnd-kit` | キーボード操作とスクリーンリーダーに対応します。`react-dnd` は保守が停滞し、HTML5のドラッグ&ドロップ由来の制約を引きずっています |
| 状態管理 | Zustand と Immer | ドキュメント木の編集において、Immerのパッチ列はそのまま undo / redo の基盤になり、後の協調編集の基盤にもなります |
| キャンバス | DOM（Document Object Model、文書オブジェクトモデル）をReactコンポーネントとして扱う | Canvas や WebGL による描画は、選択、テキスト編集、アクセシビリティを自前で作り直すことを意味します |
| フォーム | React Hook Form とマニフェストからの動的生成 | コンポーネント追加時にインスペクタのコードを書かずに済みます（[ADR-0002](../ADR-0002-component-manifest-single-source/ADR-0002-component-manifest-single-source-ja.md)） |
| サーバ通信 | TanStack Query と、プレビュー同期のための WebSocket | |

このスタックからは、さらに2つの決定が従います。キャンバスの忠実度をどう扱うかと、v1における協調編集の
定義です。

### キャンバスの忠実度 — 近似プレビューと実機ミラーの二段構え

Webのキャンバスは**3つ目のレンダラ**であり、SwiftUI や Compose と完全に一致させることは原理的に不可能
です。フォントメトリクス、行分割、スクロール挙動がいずれも異なるからです。そこでプレビューを二段構えに
します。

1. **近似プレビュー**。ブラウザ上で、編集中の高速なフィードバックのために使います。近似であることを
   画面上で明示します。
2. **実機ミラー**。エディタが下書きドキュメントを WebSocket でブロードキャストし、実機のアプリ、
   すなわち開発者モードまたは専用プレビューアプリがそれを受け取って**本物のレンダラで**描画します。
   端末はQRコードでセッションに参加します。公開前の確認はこちらで行い、こちらを正とします。

実機ミラーは「あとで付ける機能」ではなく**マイルストーンM2の必須要件**です。これがなければ、編集者は
ブラウザの見た目を信じて公開し、実機で画面が崩れます。起こりうる事故ではなく、確実に起こる事故です。

### 協調編集

v1では**CRDTを採用しません**。ドキュメントに `version` フィールドを持たせた楽観ロックと、同じ画面に誰が
いるかを示すプレゼンス表示にとどめます。想定される同時実行は、1画面を同時に触るのが1〜2人という規模です。
それに対して、Yjs のようなライブラリの導入コストと、自動マージされた木が構造上は妥当でも意味的に壊れる
リスクは、いずれも得られる利点に見合いません。

## 根拠

インスペクタをマニフェストから描画することが、エディタの拡張を安く保ちます。これが成り立つのは、
マニフェストが型だけでなくエディタ用のメタデータも持つからです。したがってスタックは、生成された
TypeScript をそのまま使えるように選んでいます。バックエンドが同じ言語である理由も同じです
（[ADR-0007](../ADR-0007-backend-stack/ADR-0007-backend-stack-ja.md)）。

Immerのパッチは三役をこなします。undo / redo、実機ミラーへの下書きの送信、そして将来協調編集が必要に
なったときにマージ戦略が扱う変更単位です。いまパッチ方式のストアを選んでおくことで、今日の費用を払わずに
その扉を開けたままにできます。

## 代償

ブラウザのプレビューは、細部において常に実機と食い違います。画面はそのことを言い続ける必要があり、
実現できない忠実さを暗にほのめかしてはいけません。その答えが実機ミラーであり、結果としてM2は、
エディタの完成に先立って少なくとも1つのクライアントSDKが描画できることに依存します。

楽観ロックを採るということは、1つの画面を2人が同時に編集した場合、マージではなく競合が見えるという
ことです。この規模ではそれが意図した挙動です。

## 再検討のトリガー

1つの画面を3人以上が日常的に同時編集するようになった場合、または競合による拒否が頻発して編集者が
ツールを避け始めた場合、CRDTの判断を見直します。
