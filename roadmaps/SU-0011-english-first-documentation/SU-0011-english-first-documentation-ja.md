## はじめに

この項目は、リポジトリのすべてのドキュメントを英語を主、日本語をその対訳として持つ形に揃えることを
提案します。Spectre UI は、サーバードリブンUI（Server-Driven UI、SDUI）のためのクロスプラット
フォームライブラリです。サーバが配信したUI定義ドキュメントを、iOS と Android のネイティブSDK
（Software Development Kit、ソフトウェア開発キット）が解釈して描画します。ADR（Architecture
Decision Record、アーキテクチャ決定記録）、ロードマップ項目、READMEは、すでに英語と日本語の組に
なっています。組になっていないのが、`docs/adr/` を除く `docs/` 以下の10ページです。いずれも日本語版
しかありません。

## 動機

プラットフォーム間で共有するのは仕様です。クライアントのレンダラは SwiftUI、Jetpack Compose、React
とプラットフォームごとに書き、それらを1つの振る舞いに縛るのは、共有コードではなく仕様と適合性
コーパスです。仕様が1つの言語でしか書かれていなければ、適合するレンダラを書ける人は、その言語を読める
人だけになります。

組で持つという規則はすでにあり、`docs/` はその穴です。英語のADRは、ドキュメントのスキーマの根拠として
`docs/spec/schema.md` を引きます。その引用を辿った読者が着くのは日本語のページです。文章規範は、
どの文書も単独で読めること、用語は読者が出会う場所で定義することを求めています。引用の先で言語が
変わることは、読者が詳細を求めたまさにその地点で、その約束を破ります。

ドキュメントサイトは、同じ隔たりをさらに広げます。MkDocs は `docs/` を日本語のサイトとして構築し、
英語のADRはナビゲーションに載せず、各ページ冒頭の言語切り替えリンクから辿らせます。英語で訪れた
読者は、ナビゲーションに並ぶページ名を開いて、そこが日本語で書かれていることに気付きます。

費用を決めるのは着手の時期です。`docs/spec/` 以下のページは、マイルストーン M0 が仕様を凍結するまで
変わり続けます。いま訳せば、M0 が書き換える文章の翻訳を買うことになります。設計のページには、その
書き換えの予定がありません。

## 詳細設計

1. **組で持つ規則を `docs/` にも広げます。** `docs/` 以下のページは英語版 `X.md` と日本語版
   `X-ja.md` を組で持つこと、片方を変えたら同じ変更でもう片方も更新することを、`CLAUDE.md` と
   `.agent-workflows/` 以下の文章規範に書きます。
2. **各ページの日本語版を `-ja.md` のパスへ移し、**ADRのページと同じ言語切り替え行を両方の先頭に
   置きます。
3. **設計の4ドキュメントの英語版を書きます。** `tech-selection.md`、`architecture.md`、
   `editor.md`、`compatibility.md` と、サイトのホームである `index.md` です。これらのページには
   仕様の書き換えが控えていないため、訳した内容がそのまま残ります。
4. **仕様の4ドキュメントの英語版を、M0 の凍結後に書きます。** `spec/schema.md`、
   `spec/components.md`、`spec/expression.md`、`spec/actions.md` です
   （[SU-0001](../SU-0001-m0-specification-freeze/SU-0001-m0-specification-freeze-ja.md)）。
5. **マイルストーンの概観である `roadmap.md` の英語版を書きます。** 要約の対象であるロードマップ
   項目と並べて保ちます。
6. **各ドキュメントが同じ言語の中でリンクするよう、参照先を張り替えます。** 現在 `docs/` 以下の
   ページを引いているのは、2つのREADME、サイトのホーム、ADR、ロードマップ項目です。`mkdocs.yml` と
   `scripts/site_links.py` も同じページを指しています。
7. **英語のページをサイトのビルドに載せます。** 扱いは英語のADRと同じで、ナビゲーションには載せず、
   言語切り替えリンクから辿らせ、`not_in_nav` で除外します。
8. **対訳の有無を検査する仕組みを Pages のワークフローに足し、**`docs/` 以下のページに対応する
   もう一方の言語のページがなければビルドを落とします。`mkdocs build --strict` が捕まえるのは
   リンク切れであり、対訳の欠落は別種の欠陥で、いまはどの検査も報告しません。

## 検討した代替案

- **`docs/` は日本語のままとし、求められたページだけを訳す。** 却下します。問い合わせを受けてから
  訳したものは、それが判断材料になるはずだった時点を過ぎて届きます。しかも仕様は、外部の実装者が
  最初に読むドキュメントです。
- **サイトのビルド時に機械翻訳で英語版を生成する。** 却下します。文章規範は、どちらの言語もその言語の
  読者にとって自然に読めることを求めています。ビルドが生成した文章には、責任を持つ査読者がいません。
  仕様において規範的な一文を訳し損ねれば、その一文から作られたすべてのランタイムが欠陥を受け継ぎます。
- **英語だけを残し、日本語のページを捨てる。** 却下します。チームが議論し査読するのは日本語であり、
  `docs/adr/` と `roadmaps/` の組は、2言語の運用が実際に回ることを示しています。
- **`docs/spec/` も含めて一度に訳す。** 却下します。M0 はその4ページを書き換えるため、同じ結果に
  対して費用を2度払うことになります。

    済みの `docs/adr/ADR-0001-client-rendering-strategy.md` にも未解消のまま残っており、英語の文章に
    ついてこのリポジトリのtextlintがすでに許容している水準の基準として、その記録を使いました。
    `.textlintrc.json` を緩めてこの状態にしたわけではありません。
